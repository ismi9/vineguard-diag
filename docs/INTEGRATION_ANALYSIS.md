# Аналіз інтеграції з наявними репозиторіями

Питання: чи доцільно замість нового репозиторію інтегрувати проект
(VineGuard Diag) в один із наявних?

## Кандидати

| Репозиторій | Домен | Стан | Вердикт |
|---|---|---|---|
| **vinemind-ai** | «AI-платформа для аналізу виноградників» — порожній заповіт (README + .gitignore, 1 КБ) | заготовка з 2026-07-28 | **Найкращий кандидат — платформа-парасолька, але не замінник** |
| grapevine-model (VineSeason) | біофізіологічна модель сезону винограду, статичний JS | активний, v1.0.0 | суміжний домен; інтеграція на рівні даних, не коду |
| arch-trellis-calculator | калькулятор шпалери | активний | незалежний інструмент, без AI-бази |
| drawdb / RuFloUI / langflow … | схеми, дашборди, LLM-оркестрація | дзеркала | домен не повʼязаний |

## Висновок

**1. Новий репозиторій створювати — так** (що й зроблено: `vineguard-diag`).

**2. Інтеграція з vinemind-ai — доцільна і запланована, у ролі модуля.**
`vinemind-ai` позиціонується як платформа аналізу виноградників (структура
`apps/web`, `ai/`, `database/` у його README) і наразі порожня — саме туди
VineGuard Diag логічно стає першим робочим модулем: `web/` → apps/web,
`api/diagnose.js` → ai/, `schema/` + база карток → database/. Об'єднання зараз
б не дало б вигоди (платформи ще нема), а окремий репозиторій дає незалежний
релізний цикл, CI і демо. Рекомендація: розвивати тут; коли vinemind-ai
набере інші модулі (метео, облік обробок, планування) — перенести як модуль
першим, формат карток уже спроектовано сумісним.

**3. Інтеграція з grapevine-model — на рівні даних, не коду.** Спільна
термінологія: сорти (мускат білий, одеський…), елементи живлення
(N/P/K/Mg/B/Zn — ті самі, що фактори моделі), фази вегетації. Перспективний
обмін: картка діагностики «дефіцит Mg, середній» → рекомендація VineSeason
`mgSupply=0.5` для сценарію «що буде з урожаєм»; forecasts VineSeason →
попередження ризиків мілдью в VineGuard. Це API/дані (JSON), не спільний код:
у VineSeason немає AI-беку й не повинно бути (ТЗ моделі вимагає відсутності
залежності від AI).

## Виконані кроки

- Новий репозиторій `vineguard-diag` створено і заповнено (це репо).
- Інтеграційна точка `save_card_to_database()` в `web/app.js` вже ізольована
  однією функцією — підключення бекенду vinemind-ai не потребує змін UI.
- Формат картки (schema) задокументований як контракт обміну для обох платформ.
